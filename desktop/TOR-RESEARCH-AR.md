# مراجعة Tor وGetTor وArti وتطبيقها في سَنَد الحرمين

تاريخ المراجعة: 31 أكتوبر 2026. نطاق التطبيق: مصدر النسخة المكتبية في هذا المستودع. لم تُضف تبعية إلى Tor أو Arti، ولم يُغيّر مسار اتصال المستخدم إلى شبكة Tor.

## ما فُحص بالفعل

- المسار المطلوب `TheTorProject/gettorbrowser:torbrowser-releases` بالكامل: يحتوي ملفي README وخصائص Git LFS، مع حزم منشورة وتواقيع منفصلة في Releases. هذا مسار توزيع إصدارات، ويُفيد في موثوقية الحزم واختيارها والتحقق منها؛ لا يحتوي محرك عرض صفحات.
- مستودع GetTor التاريخي عند `fc9e1ed212d54cf682601a1caaa7e289a43d50cf`: تصميم فصل منطق اختيار الحزمة عن قنوات التوزيع، وملفات `scripts/update_files` و`scripts/update_git`. هذه نسخة مؤرشفة؛ لم تُنسخ إجراءات حذف الإصدارات أو المشاريع الموجودة في تلك السكربتات.
- مرآة `torproject/tor`: فرع main الحالي يحيل إلى GitLab، ولم يعد يحتوي شجرة المحرك. لذلك لا نفترض أن وجود حساب GitHub يعني تزامنًا حاليًا لكل المستودعات. روجعت أيضًا ملفات التشفير والعشوائية في فرع release-0.4.7 التاريخي للمقارنة، مع مواصفات Tor المنشورة الحالية.
- لم يظهر مستودع `torproject/arti` عند التحقق. استُخدمت وثائق Arti ومصدر Rust المنشور على نطاق Tor الرسمي، بما فيه إدارة الذاكرة ومفاتيح/تشفير الدارات.
- مصادر Electron المطابقة للإصدار 45.1.0، خاصة safeStorage غير المتزامن، بدل استعمال الواجهات المتزامنة المهجورة.

## التشفير وإدارة دورة الحياة

`state-encryption.cjs` يستخدم WebCrypto القياسي، وليس تنفيذًا جديدًا لخوارزمية تشفير. تُولّد المفاتيح وnonces من مولّد عشوائي تشفيري. يُستورد مفتاح البيانات كـ CryptoKey غير قابل للاستخراج، وتُصفّر النسخة الخام المؤقتة بعد الاستيراد وتغليف المفتاح. يُخزّن الملف المغلف فقط، ولا يُرسل أي مفتاح أو سجل إلى خدمة خارجية.

`store.cjs` يرحّل السجل والمفضلة والإعدادات الأصلية إلى `browser-state-v2.enc` بعد تنقيتها بالقواعد الموجودة. تبقى الكتابات متسلسلة مع تأخير التجميع الموجود، وتتخطى اللقطات التي لم تتغير. التشفير وحفظ الملف غير متزامنين، ويُنتظر آخر حفظ عند إغلاق التطبيق. تدوير مفتاح خزنة النظام يعيد تغليف مفتاح البيانات دون فقد الحالة.

في Windows يحمي موفّر Electron المفتاح باستخدام DPAPI؛ وفي macOS يستخدم خزنة النظام. في Linux لا نعد `basic_text` أو موفّرًا مجهولًا خزنة آمنة. إذا لم تتوفر خزنة موثوقة ولم يوجد ملف مشفر، يستمر سلوك التخزين القديم مع إظهار أن البيانات غير مشفرة. إذا وجد ملف مشفر وتعذّر الوصول إلى المفتاح، لا يحدث أي رجوع تلقائي إلى JSON قديم ولا استبدال الملف المشفر. تعرض صفحة «حول Sanad» الحالة الفعلية.

## حدود النتيجة

- حماية DPAPI في Windows مرتبطة بحساب نظام التشغيل، ولا تمنع برنامجًا ضارًا يعمل بصلاحيات الحساب نفسه. نقل الملف المشفر إلى مستخدم/جهاز آخر قد يمنع فتحه؛ يجب الاحتفاظ بإمكانية الوصول إلى حساب وخزنة النظام.
- النطاق هو سجل التطبيق ومفضلته وإعداداته المحلية. ملفات المستخدم المنزّلة، ملفات المفضلة التي يصدّرها بنفسه، تخزين المواقع وذاكرة الصفحات لها نطاقات منفصلة. إعداد تشفير كوكيز Electron الموجود في الحزمة باقٍ.
- هذه ليست شهادة تدقيق تشفيري مستقلة. لا يترتب على ذلك اتصال بشبكة Tor أو إخفاء عنوان IP أو تكافؤ مع Tor Browser. HTTPS والتحقق من الشهادات يستمران عبر Chromium كما هما.
- SHA-256 يثبت تطابق بايتات مع قيمة مرجعية موثوقة، والتوقيع يثبت هوية الناشر وفق سلسلة الثقة؛ لا نستبدل توقيع Microsoft Store بقيمة hash أو ندّعي أن نسخة قديمة غير موقعة أصبحت موقعة.
- خفض الطلبات والعمل المتكرر قابل للتحقق. لا توجد نسبة عامة مزعومة لتسريع كل مواقع الإنترنت. استبدال الصفحة المكتبية الثقيلة بالواجهة المستقلة يستفيد من تقليل ملفات تنسيق الويب الذي نُفذ سابقًا، ولا يُحسب كقياس سرعة جديد.
- التغيير في مصدر التطبيق يحتاج إصدارًا مكتبيًا وتوزيعه عبر مسار المتجر. دمج المصدر وحده لا يحدّث النسخ المثبتة، ولا يغيّر ملفات المستخدم عبر صفحة الويب.

## التحقق

اختبارات الوحدة تستخدم AES-GCM الحقيقي وموفرًا بديلًا لخزنة النظام؛ لا تُعد إثباتًا لاستخدام DPAPI الفعلي. اختبار Windows المنفصل يشغّل Electron مع خزنة النظام الفعلية، ثم يتحقق من ترحيل JSON إلى ملف مشفر، إعادة التشغيل وفك التشفير، ورفض الملف المعدّل دون استبداله. اختبار المثبّت يفتح صفحة «حول Sanad» في التطبيق المثبت ويتحقق من عرض حالة التشفير، ويحفظ إثبات Windows ضمن مخرجات CI. تبقى اختبارات التوقيعات والحزم والعزل والكوكيز والصفحات والتنزيلات قائمة.
