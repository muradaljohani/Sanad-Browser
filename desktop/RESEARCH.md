## Reader and page tools

Mozilla Readability runs in isolated world 1001 against `document.cloneNode(true)`. Parsing has an element/time limit and only a title, direction and bounded plain text cross into the trusted shell. Readability HTML is never inserted there; the original page remains intact. The text is ephemeral and is not written to history or sent to a server.

Context actions use Chromium's actual context metadata, reject executable/local/credential-bearing link URLs, preserve literal selected searches and honour native edit capabilities. They cannot execute arbitrary commands. Saved PDF/PNG/MHTML files are created only by explicit page-tool actions and an OS save dialog. PNG captures the visible content viewport. MHTML is an export for compatible offline readers; arbitrary `file://` navigation remains rejected.

Private mode has both an isolated temporary Electron session and a first-party Sanad UI hint. The latter disables typing suggestions, client/server search cache use and persisted search history. It is not added to unrelated site URLs or user agents. A valid login remains in the normal profile only; new profiles must log in once.

## Verification boundaries

The executable integration journey tests sandbox configuration/remote Node absence, popup opener continuity, actual network blocking, navigation, private cookie/localStorage reset, normal cookie persistence after restart, DOM/CSS/JS, rendered find layout, actual downloads, PDF, PNG, MHTML and reader text with the original DOM retained. Browser UI tests cover mobile/desktop sizes and both themes, tab filtering/pinning, safe bookmark imports, remote-suggestion opt-out and native private-search propagation. Windows/Linux binaries are built from the same source by GitHub Actions.

This report does not claim every Chrome service or extension API, a complete multi-engine browser, identical performance on all devices, or a from-source build of Chromium/Servo/Ladybird/WebKit/Gecko. Engines/frameworks with incompatible host contracts are reviewed separately so the existing project remains usable.

## Internal tabs, update service and application install research (1.2.0)

- [thanhlmm/electron-multiple-tabs](https://github.com/thanhlmm/electron-multiple-tabs), `server/src/index.ts`: studied tab/view and shortcut lifecycle. Its older BrowserView and contextIsolation choices are not copied. Sanad retains current WebContentsView and strict isolation.
- [Min view manager](https://github.com/minbrowser/min/blob/master/main/viewManager.js) and [Electron window-open](https://www.electronjs.org/docs/latest/api/window-open): adopt Electron-created popup contents to retain POST/opener behaviour. [setWindowOpenHandler](https://www.electronjs.org/docs/latest/api/web-contents#contentssetwindowopenhandlerhandler) specifically documents the missing webContents for background tabs; Sanad now explicitly loads that case, forwards referrer/POST metadata, preserves background selection and handles script-driven close.
- [WebView2Samples](https://github.com/MicrosoftEdge/WebView2Samples), `SampleApps/WebView2APISample/AppWindow.cpp`: reviewed NewWindowRequested/deferral ownership; equivalent lifecycle is implemented with Electron, without adding another engine.
- The supplied `safwanams/PyQt5-Browser` URL returned 404 through GitHub and could not be verified. No code or behaviour is falsely attributed to it.
- [electron/update.electronjs.org](https://github.com/electron/update.electronjs.org) and [Electron updating guide](https://www.electronjs.org/docs/latest/tutorial/updates): public-repository/format prerequisites prevent honest automatic installation for the existing private NSIS distribution. A bounded first-party metadata check is implemented, with explicit manual installation and no credential embedding.
- [GitHub Desktop About](https://github.com/desktop/desktop/blob/development/app/src/ui/about/about.tsx): version/architecture, development gating, checking/error states, last successful check, release notes and license access inform Sanad's About panel. Source code is not copied.
- [PWABuilder](https://github.com/pwa-builder/PWABuilder) and [PWA Starter manifest](https://github.com/pwa-builder/pwa-starter/blob/main/public/manifest.json): the companion Sanad web project adds a distinct standalone manifest, focus-existing launch hint, explicit installation action and a narrowly scoped offline notice; it does not duplicate this native executable.
- [Nativefier](https://github.com/nativefier/nativefier) is archived/unmaintained. Its independent-window concept is served by the existing maintained Electron integration rather than adding an obsolete wrapper.
- [daedalOS process functions](https://github.com/DustinBrett/daedalOS/blob/main/contexts/process/functions.ts) and [window focus](https://github.com/DustinBrett/daedalOS/blob/main/components/system/Window/useNextFocusable.ts): reviewed stable identity, cleanup and next-focus management. Sanad's tab close returns to its opener and reuses named windows. No desktop simulator is added over the existing browser UI.
- The supplied `mercury-workshop/anuraOS` resolves in research to [MercuryWorkshop/anuraOS](https://github.com/MercuryWorkshop/anuraOS). Its [internal API](https://github.com/MercuryWorkshop/anuraOS/blob/main/documentation/Anura-API.md) separates window/process/URI handling and offline PWA concerns. Sanad keeps a narrow tab command interface and public-only offline cache. The Linux emulator, proxy transport and AGPL code are not embedded.

Additional executable tests cover middle/Ctrl/Shift/blank opening, POST bodies, named window reuse, opener scripting, script close, child survival, private popups, isolated zoom, About update states/copy and actual sandboxed Chromium notices.
